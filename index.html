AI Engineering

AI 導入成果

從「AI 輔助人」到「人輔助 AI」：把團隊開發經驗封裝成 AI 可重複執行的流程，AI 負責撰寫與初審，人負責定規格與把關。從 GitHub Copilot Agent 到 Claude Code，6 人團隊全數納入日常開發。

  • Code Review 一個指令完成：將團隊 Review 規範與 Commit 流程封裝成 AI 流程，原本需兩次手動操作，改為一個指令完成 Review → Commit，任何成員執行都得到一致的審查品質
  • 每日自動 Code Review：排程只審查新增的變更，問題連同來源 Commit 與作者推送團隊通知，程式碼被改壞時不需等到人工發現
  • 規格驅動的 AI 開發：需求先拆成小顆粒度的計畫與 Task，經人確認後 AI 才能動手；每個 Task 附驗收條件，以實際結果驗收，不以「AI 說完成」為準
  • AI 直接操作遊戲編輯器：透過 MCP 讓 AI 操作 Cocos Creator 的節點、元件、Prefab 與場景
  • 開發知識沉澱：開發決策寫成 ADR 文件回存知識庫，下次開發自動引用，形成「開發 → Review → Commit → 知識累積」的迴圈
  • 企劃也能用 AI 參與開發：與企劃訂定協作規範（暫代素材命名、非正式需求另切 Branch、週會先提緊急需求），企劃在 Branch 上開發，正式規格經工作流進主線，暫時需求不影響主線
  • README 單一資訊來源：網址、測試環境、建置任務、分支規則集中記錄，減少重複詢問，新成員可直接從文件上手

實作細節（/ts-review、/cocos-develop、SubAgent 與 Context Engineering 設計）請見作品區「AI 工作流作品集」。
